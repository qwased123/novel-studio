# Novel Studio

本地优先的中文长篇小说 AI 写作工作台。正文和记忆保存在本机 SQLite 中，模型输出先成为提案，接受后才会写入正式版本。

## 当前默认入口

默认前端已经切换到重构中的 Novel Studio 工作台，而不是下面保留的旧版卷/章编辑器。它把“与作者协商”和“执行写作、审查、记忆管理”明确分开：

- 主 Agent 是唯一的用户入口，负责对话、理解需求、拆分任务和汇总结果，不直接写正文或项目文件。
- 执行角色包括正文、上下文、优先级、记忆文件管理、正文审查和逻辑审查 Agent；每个角色有独立的提示词预设和模型配置。提示词按可排序的消息块保存，每块可以配置名称、启用状态、System/User/Assistant 角色、触发范围、深度、顺序和正文；默认块同样可以编辑或停用，只是不允许删除。
- 人类材料分为正文、设定集和规划，并分别保存草稿区、正式区。设定集允许草稿、多个版本与废弃内容，不强加“任务地点”等固定字段。
- AI 记忆与原始材料分离。每条正式记忆带有一个 memory skill（摘要、用途、关键词、关联和来源版本），上下文先读目录和 skill，必要时才读完整内容。
- 草稿进入正式区时，会先留下逻辑预检与忠实度审查任务；正式资料、派生记忆、skill 和记忆目录在同一 SQLite 事务内激活，避免出现资料已正式化但 AI 记忆未同步的状态。
- 资料更新使用版本号进行乐观并发校验。解决的审查报告会从待处理列表删除；正式记忆的退役需要明确确认后硬删除。

当前的上下文和优先级角色已经按上述调用顺序记录任务，但选择器仍是可运行的确定性规则，等待后续接入对应的 Agent 模型调用。正文生成、模型审查和记忆蒸馏也保留了这条接口边界，尚未在这个纵向切片中实现完整后台任务执行。

开发模式运行后访问 `http://127.0.0.1:5173/`。

## 当前能力

- 作品、卷、章和场景规划，TipTap 富文本正文编辑与不可变版本历史
- 故事圣经、可追溯事实、伏笔、记忆冲突和全文搜索
- 总纲、分卷、章节、场景、选区改写，以及一致性、情节和文风审校
- OpenAI、Anthropic 和 OpenAI-compatible 模型，按角色独立配置
- 持久化 AI 队列、流式结果、取消、失败重试、上下文快照和提案审批
- 蓝灯/绿灯/冷存档上下文策略，写作 Agent 可主动查询记忆并在重大分叉时等待作者决策
- 定稿后自动提取接续记忆，每五章生成可追溯的阶段弧线提案；文风审校含本地去 AI 味规则扫描
- TXT、Markdown、EPUB 和完整 `.novelstudio` 项目包导入导出

## 运行

需要 Node.js 22 或更新版本。

```bash
npm install
npm run dev
```

开发模式下，Web 默认运行在 `http://127.0.0.1:5173`，API 运行在 `http://127.0.0.1:8787`。生产方式为：

```bash
npm run build
npm start
```

生产服务在 `http://127.0.0.1:8787` 同时提供页面和 API，只监听本机回环地址。

## 模型配置

打开作品后进入“模型配置”。模型配置与 Agent 分离，Agent 只引用已经保存并启用的配置。当前支持 OpenAI、Anthropic 和 OpenAI-compatible 供应商，以及以下参数：

- Base URL 和 API Key
- 从供应商接口拉取可用模型
- 独立的模型 ID 手动输入框和可用模型下拉框
- Temperature、Top P 和 `none` / `low` / `medium` / `high` 推理强度
- 上下文长度和最大回复长度
- 配置启用状态

OpenAI-compatible 通常填写形如 `http://127.0.0.1:8000/v1` 的 Base URL。模型发现会补全 `/v1/models` 路径，并拒绝携带密钥跟随重定向。手动输入模型 ID 不会过滤已拉取的模型列表；从下拉框选择模型时会回填模型 ID。

API Key 写入数据目录下的 `credentials.json`，文件权限为 `0600`。页面不会回显已保存的密钥；输入框留空会保留原密钥。

## 记忆与上下文

系统不把整部小说反复塞进提示词，而是保留不同用途的记忆层：

1. 文档每次保存产生不可变原文版本，这是最终事实来源。
2. 已确认章节可由记忆模型抽取带证据的事实、章节摘要和伏笔；写回前必须人工接受。
3. 身份和世界规则等永久事实发生冲突时不会静默覆盖，而会进入冲突队列；位置、持有物等可变状态保留历史记录。
4. 修改旧章后，源自旧版本的事实会标记为失效，该章及后续章节摘要会标记为过期。
5. 每次 AI 任务只装配硬约束、当前纲要、最近三章摘要或尾部、匹配实体、生效事实、开放伏笔和检索片段。可选材料超过预算时按优先级丢弃。
6. 上下文上限为约 48,000 tokens，并预留 2,000 tokens；运行前可以查看实际材料并排除非必选项。任务会保存当时的上下文、模型和提示词快照。
7. 搜索先用中文 FTS5，再在已配置向量模型时加入 sqlite-vec 语义结果。正文和设定按约 1,400 字符切片并带 160 字符重叠。
8. 上下文材料按蓝灯（硬约束）、绿灯（预算内按需注入）和冷存档（仅预览或主动查询）标记；超预算材料不会静默挤占输出空间。
9. 写作模型可以主动查询当前有效事实、章节摘要和阶段弧线；重大分叉会暂停为待决策任务，作者回复后从已生成草稿末尾继续。

这套机制能降低长篇创作中的遗忘、串设定和无效复述，但不能保证模型永不产生错误；版本追溯、证据字段、冲突队列和人工审批是最后的控制层。

Agent 的模型循环通过 `apps/server/src/agent-runtime.ts` 与领域编排隔离。业务层只提交模型配置和领域工具，不引用某个框架的模型或工具类型；当前默认适配器使用 Vercel AI SDK。任务队列、上下文、记忆工具、作者决策和提案审批归 Novel Studio 管理。后续评估其他内核时，应通过这个边界并跑验证，不直接迁移产品状态。

整章生成会按场景顺序分别调用正文模型。后续场景只获得已完成场景名和上一场末尾，不会把刚生成的全部正文重复送回模型，从源头减少重复与“流口水”。选区改写则绑定文档版本和精确位置，接受时只替换原选区；正文变化后旧提案会拒绝覆盖。

## 数据与备份

默认数据目录是项目根目录的 `data/`，可以在启动前覆盖：

```bash
NOVEL_STUDIO_DATA_DIR=/absolute/path/to/novel-data npm start
```

主要文件包括：

- `novel-studio.sqlite`：作品、版本、记忆、任务和模型角色配置
- `novel-studio.sqlite-wal`、`novel-studio.sqlite-shm`：服务运行时可能存在的 SQLite 辅助文件
- `credentials.json`：按模型角色保存的 API Key

工作台中的“完整项目包”适合逐作品备份和迁移，包含正文版本、结构化记忆、任务和提案，不包含 API Key、全局模型配置或可重建的向量索引。若要复制整个数据目录，先停止服务，再一并复制上述 SQLite 文件和凭据文件。
